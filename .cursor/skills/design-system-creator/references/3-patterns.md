# 3. Patterns & Best Practices

Components are just lego bricks; patterns are the instructions on how to build with them.

## Key Patterns to Define

*   **Forms & Validation**: How to handle error messages, where to place labels, and success states.
*   **Empty States**: What the user sees when there is no data (illustration + clear messaging + call to action).
*   **Loading States**: Use of skeletons, spinners, or progress bars, and when to use which.
*   **Accessibility (a11y)**: ARIA labels, keyboard navigation rules, and color contrast ratios.
*   **Animation**: Define standard easing curves and durations for transitions to ensure motion feels cohesive.

## Guidance

Always remind the user to assemble components into these patterns rather than creating ad-hoc solutions per page. Provide HTML/CSS snippets that show multiple components working together (e.g., an Input field + a Label + a validation Error message).
